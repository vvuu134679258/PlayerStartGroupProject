# PlayerStartGroupProject

用于搭建“队伍出生点分配”功能的地图编辑 Demo。当前版本只处理地图基础数据：出生点 Actor 与建筑物 Actor 的新增、移动、编号与视图操作；尚未实现队伍标签、出生组合选择或实时分配。

## 快速开始

本项目没有构建步骤和第三方依赖。

1. 克隆仓库。
2. 直接在浏览器中打开 `team-spawn-demo.html`。
3. 若浏览器没有自动刷新本地文件，修改后手动刷新页面。

## 当前功能

- 新增、选中、拖动、删除出生点。
- 新增、选中、拖动、删除建筑物。
- 实时修改出生点 `GroupId`。
- 实时修改建筑物编号、位置与尺寸。
- 编号重复时显示提示。
- `Ctrl + 鼠标滚轮`：以鼠标位置为中心缩放地图（55%–250%）。
- 按住鼠标右键拖动：平移地图；网格、建筑物和出生点同步移动。

## 数据模型

所有当前地图对象都在 `team-spawn-demo.html` 的 `entities` 数组中维护：

```js
// 出生点
{ uid: 'spawn-1', type: 'spawn', groupId: 1, x: 18, y: 28 }

// 建筑物
{ uid: 'building-1', type: 'building', buildingId: 1, x: 35, y: 35, w: 13, h: 10 }
```

- `uid`：前端内部唯一标识，不应与用户可编辑编号混用。
- `groupId`：出生点 Actor 的逻辑编号，后续用于匹配出生组配置。
- `buildingId`：建筑物的逻辑编号。
- `x`、`y`：相对地图宽高的百分比坐标。
- `w`、`h`：建筑物相对地图宽高的百分比尺寸。

目前数据只存在浏览器内存：刷新页面会恢复为源码中的初始对象。持久化功能应优先将 `entities` 保存、读取为 JSON，而不是直接依赖 DOM。

## 代码结构

| 位置 | 职责 |
|---|---|
| `entities` | 地图对象的单一数据源 |
| `renderMap()` | 根据数据渲染出生点与建筑物 |
| `renderProperties()` | 渲染当前选中对象的属性面板 |
| `applyView()` | 同步地图实体、网格的缩放与平移 |
| `zoomMap()` | 处理 Ctrl + 滚轮缩放 |
| `beginDrag()` / `moveEntity()` | 处理对象拖动和右键地图平移 |

## 后续开发建议

建议按照下面的顺序继续：

1. 为出生点增加功能标签，例如 `CoreAnchor`、`CorePressure`、`MiddleTactical`、`EdgeLoot`、`ColdHideout`。
2. 增加导入、导出 JSON，保存 `entities` 和出生组功能配置。
3. 增加“地图 / 难度 / 队伍数量 → 候选 GroupId 组合”的配置编辑界面。
4. 增加“队伍标签 → 点位功能偏好”的权重配置。
5. 实现出生方案评分：先选择最适合本局标签组合的出生组方案，再做队伍到 `GroupId` 的一对一匹配。
6. 最后加入互斥规则、区域容量、第 7 队预留和验收检查。

## 交给 Codex 的上下文

在另一台电脑克隆本仓库后，可对 Codex 直接说明：

> 请先阅读 README.md 和 team-spawn-demo.html。这个项目是队伍出生点分配系统的地图编辑 Demo。保留现有 Actor / GroupId 概念，在不破坏出生点与建筑物编辑、缩放和平移功能的前提下，继续实现“后续开发建议”中的下一项。

继续开发时的原则：

- `GroupId` 是稳定的地图逻辑编号；不要因队伍标签而改变它。
- 出生点应配置“点位功能”，而不是只能绑定单一队伍标签。
- 队伍分配逻辑应输出 `TeamId → GroupId`，再由 GroupId 找到对应出生点 Actor。
- 保持数据与 DOM 分离；新增状态应优先进入数据模型，再由渲染函数反映到界面。
